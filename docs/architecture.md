# Як усе влаштоване

Систему можна було б зібрати навпаки: віддати розум ESP8266, який має Wi-Fi, пам'ять і
годинник, а Nanit лишити виконавцем команд. Так роблять часто — і так будинок перестає бути
будинком, щойно зникає роутер.

Тут зроблено інакше. **Nanit — головний.** Уся автоматика, охорона, налаштування й
калібрування живуть на ньому й зберігаються в його EEPROM. **ESP — шлюз:** показує
вебінтерфейс, передає команди, веде журнал і приносить час. Без нього будинок не втрачає
жодної функції — лише сторінку, годинник і журнал подій.

```
  клавіатура ─┐                                      ┌─ браузер (телефон, ноут)
              │                                      │   WebSocket :81 · HTTP :80
   датчики ───┤                                      │
              ├──►  Nanit (ATmega2560)  ◄──UART──►  ESP8266 Witty Cloud
  механіка ◄──┤       автоматика              38400    сторінка · журнал · час
              │       охорона                          мережа · OTA
   екран  ◄───┘       EEPROM
```

## П'ять принципів

1. **Nanit працює сам.** Без ESP будинок повноцінний.
2. **ESP не знає коду охорони.** Код лише проходить крізь нього в команді й перевіряється на
   Nanit. Натискання клавіатури передаються назовні тільки в сервісному режимі.
3. **Nanit надсилає коди, а не тексти.** Українські назви подій, одиниці й переклади формує
   ESP. Так Nanit економить флеш і не має справи з UTF-8.
4. **Nanit майже ніколи не блокується на передачі.** Кадр іде в порт лише тоді, коли в
   буфері вистачає місця на весь кадр; інакше він чекає наступного проходу циклу. Виняток —
   відповіді на команди (`ACK`, `NAK`, `TR`, `HI`, `KEY`): без них ESP вважав би команду
   невиконаною, тож вони чекають вільного буфера до 11 мс.
5. **Кадри йдуть у браузер як є.** ESP не вводить власної мови — сторінка розбирає те саме,
   що прийшло від Nanit. Один формат замість двох, і немає місця, де переклад міг би
   розійтися з оригіналом.

Наслідок останнього принципу приємний: щоб зрозуміти, що бачить сторінка, досить прочитати
[protocol.md](protocol.md).

## Три шари

### Nanit — прошивка будинку

Один цикл без жодної затримки, що блокує цикл: кожен модуль має `xxxUpdate(now)` і за прохід
робить щонайбільше один крок. Найдовша операція — читання DHT11, близько 4 мс раз на дві
секунди, та й воно відкладається, поки зайняті серво чи порт.

| Файл | За що відповідає |
| --- | --- |
| `zhuk_home_nanit.ino` | `setup()` і цикл: порядок, у якому опитуються модулі |
| `zh.h` | спільні типи, стан будинку, інтерфейси модулів |
| `pins.cpp` | таблиця пінів; частина залежить від версії плати й заповнюється під час роботи |
| `link.cpp` | протокол: кадри, події з підтвердженням, кеш повторів, розбір команд |
| `sensors.cpp` | датчики: DHT11, далекомір, рух, звук (переривання), вікно, освітленість, CO |
| `actuators.cpp` | серво штори, вентилятор, шлагбаум, світлофор, RGB, зумер, дисплей TM1637 |
| `automation.cpp` | вентиляція, штора, шлагбаум, світло, тривога CO, сцени |
| `security.cpp` | охорона: стани, затримки, код, блокування |
| `keypad.cpp` | сканування клавіатури 4×4 |
| `display.cpp` | екран ST7735: вісім віджетів, перемальовування порціями |
| `settings.cpp` | налаштування й калібрування в EEPROM, міграції, положення стріли |
| `diag.cpp` | сервісний режим, перевірки модулів, стан обладнання, статистика циклу |
| `boot.cpp` | ранній старт: причина перезапуску, сторожовий таймер |
| `util.cpp`, `state.cpp` | назви для протоколу, CRC-8, спільний стан будинку |

### ESP8266 — шлюз

| Файл | За що відповідає |
| --- | --- |
| `zhe.h` | спільні оголошення, версія, налаштування модуля |
| `link.cpp` | транспорт до Nanit: черга команд, повтори, підтвердження подій |
| `hub.cpp` | знімок стану для нової сторінки, журнал у пам'яті, команди від браузера |
| `web.cpp` | HTTP на `:80`, WebSocket на `:81`, привітання клієнтів порціями |
| `net.cpp` | Wi-Fi: підключення, точка доступу, перехоплення DNS, імена в мережі |
| `timesync.cpp` | NTP, правило часової зони, передача часу в Nanit |
| `evstore.cpp` | журнал подій у файлі: кільце постійного розміру |
| `logbuf.cpp` | кільцевий журнал налагодження й дзеркало в порт |
| `store.cpp` | налаштування модуля у файловій системі |
| `ota.cpp` | оновлення прошивки: `espota` і заливка з браузера |
| `web_app.h` | **згенерований** — сторінка `web/app.html`, стиснута gzip |

### Сторінка

Одна сторінка із вкладками, без фреймворків і збірки. Отримує кадри протоколу по WebSocket і
перекладає їх у стан інтерфейсу. Мережа, час, перезапуск і оновлення прошивки йдуть не
протоколом, а прямо на ESP через HTTP: це питання модуля, а не будинку, та й пароль Wi-Fi
із комою розсипався б на поля кадру.

## Структура репозиторію

```
zhuk_home/
├── nanit/
│   ├── zhuk_home_nanit/   прошивка контролера (скетч Arduino)
│   ├── host_test/         тести логіки на комп'ютері
│   ├── hw_test/           автопрогін на макеті + servo.py, gate.py, tune.py
│   └── flash.sh           зібрати й залити однією командою
├── esp/
│   ├── zhuk_home_esp/     прошивка ESP8266
│   ├── host_test/         тести транспорту, вузла й журналу
│   ├── build.sh           збірка й заливка: USB або по Wi-Fi
│   └── *.py               ws.py, tap.py, mic.py, mon.py та інші монітори
├── web/
│   ├── app.html           робоча сторінка (вшивається у прошивку)
│   ├── prototype.html     демонстрація з імітованим будинком
│   ├── plan.html          ізометрична схема макета
│   ├── pack.py            стискає сторінку у web_app.h
│   └── serve.py           локальний перегляд
└── docs/                  ця документація
```
