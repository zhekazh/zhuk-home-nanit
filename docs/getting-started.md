# Збірка, заливка, перший запуск

Прошивок дві. **Nanit** тримає всю автоматику, охорону й калібрування; **ESP8266** додає до
них мережу, час і сторінку. Оновлюються вони окремо, тож версії в них свої, і сторінка
показує обидві.

Починати треба з Nanit: без нього ESP нема чого показувати. У зворотний бік залежності
немає — будинок працює повноцінно й без вебмодуля.

## Середовище

Проєкт розроблявся й перевірявся на **Linux**. Обидві прошивки збираються в Arduino IDE на
будь-якій системі, але допоміжні скрипти Linux-специфічні: вони працюють із портом через
`stty` і читають `/dev/ttyUSB*` напряму, без pyserial.

| Система | Прошивки | Скрипти перевірок і калібрування |
| --- | --- | --- |
| Linux | Arduino IDE або `flash.sh` / `build.sh` | працюють |
| Windows | Arduino IDE | лише через WSL; порт в IDE називається `COM*` |
| macOS | Arduino IDE | потребують правки: `stty -F` там `stty -f` |

## Прошивка Nanit

### Через Arduino IDE

1. Відкрийте `nanit/zhuk_home_nanit/zhuk_home_nanit.ino`.
2. Плата: **Arduino Mega or Mega 2560**, процесор **ATmega2560**.
3. Бібліотеки: **NanitLib** з її залежностями й **Servo**. Keypad, DHT і TM1637 **не
   потрібні** — для них у прошивці власні драйвери.
4. Завантажте прошивку на плату.

Попередження NanitLib про «Install Nanit board manager» і попередження всередині самої
NanitLib на роботу не впливають.

> Якщо збірка падає з `avr/wdt.h: No such file or directory` — вибрано не ту плату: у меню
> стоїть ядро ESP8266 або ESP32. У скетчі є `#error` з підказкою саме на цей випадок.

### Однією командою

```sh
sh nanit/flash.sh                  # зібрати й залити на /dev/ttyUSB0
sh nanit/flash.sh /dev/ttyUSB1     # інший порт
sh nanit/flash.sh --build          # лише зібрати
```

Скрипт робить обидва кроки разом і перевіряє, що заливка справді відбулася. Це не зайва
обережність: **`arduino-cli upload` не компілює** — він заливає бінарник із кешу. Забути
окремий `compile` означає залити попередню версію й довго шукати, чому зміни не діють. Одна
така заливка з'їла години: Nanit лишився на старій швидкості UART, ESP уже перейшов на нову,
і зв'язок виглядав як поламане залізо.

### Перший запуск

Монітор порту: **115200 бод**, кінець рядка **NL**. Після старту має з'явитися:

```
# Zhuk Home 0.1.0 ready
```

Якщо рядка немає — плата працює на старій прошивці або не перезавантажилась. Далі варто
пройти [перший набір перевірок](testing.md#перша-перевірка-через-монітор-порту): вони
показують, які модулі відгукуються, ще до того, як ви щось калібруватимете.

## Прошивка ESP8266

### Параметри плати

Плата — **Generic ESP8266 Module**:

| Параметр | Значення |
| --- | --- |
| Flash Size | **4 МБ, файлова система 1 МБ** (`eesz=4M1M`) |
| Flash Mode | DIO |
| CPU Frequency | 80 МГц |
| lwIP Variant | v2 Lower Memory |

Потрібна бібліотека **WebSockets** (Markus Sattler) — вона не входить у ядро ESP8266, і без
неї прошивка не збереться. Решту бере ядро.

**Розкладку флешу міняти не можна.** У файловій системі лежать налаштування Wi-Fi; після
зміни розміру розділу LittleFS опиняється за іншою адресою, не монтується й форматується —
мережу доводиться вписувати заново. Саме на цей випадок облікові дані дублюються ще й у
пам'ять SDK.

### Заливка

```sh
sh esp/build.sh                    # лише скомпілювати
sh esp/build.sh usb /dev/ttyUSB1   # через USB, коли Witty на нижній платі
sh esp/build.sh ota 192.168.1.50   # по Wi-Fi, модуль лишається в порту 11
```

**Перша заливка — тільки з Arduino IDE.** Witty не входить у режим прошивки з комп'ютера:
нижня плата смикає RESET, але GPIO0 з USB не керується, тож `esptool` завжди відповідає
`Timed out waiting for packet header`. Залийте один раз із затиснутою кнопкою **FLASH**
(швидкість **115200**) — далі достатньо `ota`, і модуль можна не знімати з порту 11.

Прошивку можна оновити й з телефона: на сторінці «Система» є форма «Залити .bin». Одного разу
це врятувало модуль, який замкнувся у власній точці доступу й був недосяжний з комп'ютера.

Сторінку інтерфейсу `build.sh` перезбирає щоразу, тож нова прошивка не може отримати стару
сторінку. Як це влаштовано — [esp-module.md](esp-module.md#сторінка-у-прошивці).

### Перше підключення до мережі

Без налаштованої мережі ESP піднімає точку доступу **`ZhukHome-XXXX`** без пароля. Сторінка
відкривається сама — спрацьовує перехоплення DNS; якщо ні, наберіть `http://192.168.4.1`.

Впишіть домашню мережу (**лише 2,4 ГГц**), модуль перезапуститься й далі житиме в ній під
іменами `http://zhukhome.local` і `http://zhukhome`.

> **Якщо імена не відкриваються** — подивіться на екран макета: у нижньому рядку Nanit показує
> адресу, яку модуль отримав від роутера. mDNS працює не скрізь — його часто немає в Android
> і в гостьових мережах, — а IP видно завжди.

У режимі точки доступу віддається та сама основна сторінка: Nanit на зв'язку по UART, тож
будинок видно. А от **керування вимкнене** — точка без пароля, і скористатися ним міг би
будь-хто поруч. Сторінка пояснює це банером.

Подробиці про поведінку модуля в мережі, службовий пароль, час і журнал —
